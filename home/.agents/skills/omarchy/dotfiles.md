# Dotfiles: What to Version and How to Link

Read this before moving, symlinking, or "backing up" user configuration. The
goal is to keep the editable config in one repo while leaving generated state,
secrets, and package-owned files where they belong.

## The Rule

- **Version user config.** Anything under `~/.config/` that a user edits,
  and that should survive a reinstall, belongs in the dotfiles repo.
- **Never version generated state.** Caches, history, runtime state, browser
  profiles, and files regenerated by a theme belong outside the repo.
- **Never edit `/usr/share/omarchy/` to make a dotfile.** Read it, copy a
  template if needed, and keep the result in `~/.config/`.
- **Never commit secrets.** Use a password manager or an untracked secrets
  file; add the path to `.gitignore`.
- **Link, don't move.** The live path stays in place and points at the repo,
  so apps keep reading the same path.

A simple layout that mirrors the home directory:

```text
~/dotfiles/
├── home/                    # mirrors $HOME exactly
│   └── .config/...
├── hosts/<hostname>/        # only machine-specific overrides
│   └── .config/hypr/monitors.lua
├── packages/                # pacman/AUR lists for bootstrap
└── scripts/
    ├── link.py              # create/update symlinks
    └── install.sh           # packages + links + theme
```

`home/.config/foo` becomes a symlink at `~/.config/foo`. A host overlay in
`hosts/<hostname>/.config/...` wins over the common file.

## What Belongs in the Repo

### Hyprland / Omarchy

- `~/.config/hypr/` — `hyprland.lua`, `bindings.lua`, `input.lua`,
  `looknfeel.lua`, `hyprsunset.conf`, `xdph.conf`, `.luarc.json`.
- `~/.config/hypr/monitors.lua` and `autostart.lua` — put the real ones in
  `hosts/<hostname>/` and keep a generic fallback in `home/`.
- `~/.config/omarchy/shell.json` — bar layout, widgets, idle and lock times.
- `~/.config/omarchy/language`, `keyboard-layouts`.
- `~/.config/omarchy/extensions/` — custom Omarchy menu JSON.
- `~/.config/omarchy/hooks/` — custom event hooks.
- `~/.config/omarchy/themed/` — per-app templates.
- `~/.config/omarchy/branding/` — only if personalized.
- `~/.config/omarchy/defaults/` — only if you changed the defaults.
- `~/.config/omarchy/themes/<your-theme>/` — hand-written themes. Stock
  themes under `/usr/share/omarchy/themes/` are not yours to version.
- `~/.config/omarchy/plugins/<your-plugin>/` — only plugins you own/forked.

### Omacale

- `~/.config/omacale/settings.json` — bar, tray cascade, dashboard, lock.
- `~/.config/omarchy/plugins/omacale.bar/` — only when you edited the plugin.
  Prefer a fork/copy; an upstream reinstall overwrites a raw copy.

### Terminals and shell

- `~/.config/ghostty/config` and any local include such as `local.conf`.
- `~/.config/foot/foot.ini`, `~/.config/alacritty/alacritty.toml`,
  `~/.config/kitty/kitty.conf` if used.
- `~/.config/fish/`, `~/.config/nvim/`, `~/.config/btop/`,
  `~/.config/starship.toml`.
- `~/.config/git/config` (no credentials), `~/.config/environment.d/`,
  `~/.config/fontconfig/`.
- `~/.config/gtk-3.0/`, `~/.config/gtk-4.0/`, `mimeapps.list`,
  `hyprland-mimeapps.list`.
- `~/.config/systemd/user/` — custom units only.

### Host-specific

- Monitor layout (`monitors.lua`).
- Autostart apps (`autostart.lua`).
- Per-screen bar positions and display profiles.
- Anything that names a disk, GPU, keyboard, webcam, or host path.

## What Stays Out

- `~/.local/state/`, `~/.cache/`, `~/.local/share/`, `~/.local/share/omarchy/`.
- `~/.local/state/omarchy/current/theme` — generated theme state.
- `~/.config/omarchy/plugins-backups/` and every `*.bak*` file.
- `~/.config/omarchy/themes/*/preview.*` — large and not needed to run.
- Browser profiles (`BraveSoftware`, `chromium`, `google-chrome`,
  `microsoft-edge`, `mozilla`), Steam/Heroic, Bitwarden, `gh`, Hermes,
  `~/.local/share/opencode`.
- `~/.ssh/`, `~/.gnupg/`, tokens, API keys, `~/.face` unless you want it.
- The `superwhisper-panel` symlink to `/opt`; install the package on the new
  machine instead.
- `~/.config/omarchy/plugins/vz.lock`, `vz.notifications`, `vz.osd` are
  Omacale handover clones: if you version them, also keep their
  `*.omacale-orig` files and re-link after an Omacale update. If you do not
  need exact reproduction, let the Omacale installer recreate them.

## Symlink Practice

- **File-level** symlinks for directories apps write to (`fish`, `nvim`,
  `btop`, `gtk`, `mimeapps`). This keeps `fish_variables`, caches, and
  app-generated files local.
- **Whole-directory** symlinks for plugin and theme trees that are read-only
  and should stay centralized (`omacale.bar`, `vz.*`, custom themes).
- Use relative symlinks from the live path to the repo, so moving the repo
  breaks loudly instead of silently pointing at the wrong tree.
- Back up before replacing: move the existing target to
  `~/.dotfiles-backup/<timestamp>/`, then create the link.
- Make the linker idempotent. Running it again must only fix what changed.
- Provide `--dry-run`; never make a user discover a wrong link by losing a
  config.
- After a theme switch, an Omacale update, or a new file in the repo, run the
  linker again. Generated trees and handover clones can replace a symlink.

## What to Commit After a Customization

1. Edit the file in its live path (which is already a symlink into the repo).
2. Confirm `readlink -f <path>` points into the dotfiles repo.
3. Commit the repo.
4. If you added a new file under a whole-directory link, it is already in the
   repo; if you added a new file elsewhere, re-run the linker.
5. Never commit the result of a `theme set` under `~/.local/state`; commit the
   theme source (`colors.toml`, `shell.toml`, `hyprland.lua`, backgrounds) in
   `~/.config/omarchy/themes/<name>/` instead.

## Install on a New Machine

```bash
# Omarchy already installed
git clone <repo> ~/dotfiles
cd ~/dotfiles
./scripts/install.sh          # packages + links + theme
# or, when packages are already there:
python3 scripts/link.py
python3 scripts/link.py --dry-run   # preview only
```

The installer is expected to be idempotent. It should install packages, link
the common tree, overlay `hosts/$(hostname)`, apply the theme/wallpaper, and
restart the shell. Anything machine-specific (drivers, monitors, autostart,
paths) belongs in `hosts/<hostname>/`, not in the common tree.
